## 1. 数据结构概述

### 1.1 什么是数据结构
- 定义：计算机存储、组织数据的方式
- 数据结构的三个层次：逻辑结构、物理结构、操作集合
- 数据结构与算法的关系

### 1.2 数据结构的分类
- 逻辑结构分类：
  - 线性结构（数组、链表、栈、队列）
  - 树形结构（二叉树、堆、B树）
  - 图形结构（有向图、无向图）
  - 集合结构（散列表）
- 物理存储结构：
  - 顺序存储（连续内存）
  - 链式存储（非连续内存，指针连接）

### 1.3 抽象数据类型（ADT）
- ADT的定义：数据对象 + 数据关系 + 基本操作
- 封装与信息隐藏
- 常见ADT示例：List、Stack、Queue、Map、Set

### 1.4 数据结构的重要性
- 影响算法效率的根本因素
- 现实世界建模能力
- 面试与竞赛中的核心地位

### 1.5 复杂度度量基础
- 时间复杂度（大O表示法）
- 空间复杂度
- 最好/最坏/平均情况分析
- 常见复杂度等级：O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ)

## 2. 线性结构之数组

### 2.1 数组的定义与特性
- 连续内存空间，固定长度（静态数组）
- 随机访问 O(1)，通过索引直接寻址
- 元素类型相同，内存对齐

### 2.2 数组的基本操作及复杂度
- 访问：O(1)
- 搜索（无序）：O(n)
- 插入（末尾）：O(1)（有空间时）
- 插入（中间/开头）：O(n)（需要移动元素）
- 删除（末尾）：O(1)
- 删除（中间/开头）：O(n)

### 2.3 动态数组（如Python list, Java ArrayList）
- 动态扩容机制（通常扩容为1.5~2倍）
- 摊还分析：均摊插入时间复杂度 O(1)
- 缩容策略（防止内存浪费）

### 2.4 多维数组
- 二维数组的存储方式（行优先 vs 列优先）
- 矩阵的压缩存储（对称矩阵、稀疏矩阵）

### 2.5 数组的优缺点与适用场景
- 优点：随机访问快、内存连续、缓存友好
- 缺点：插入删除慢、大小固定（静态数组）
- 适用：频繁读取、大小已知、缓存敏感场景

### 2.6 数组在语言中的具体实现对比
- C/C++ 原生数组、std::array、std::vector
- Java 原生数组、ArrayList
- Python list 的实现特点（变长、异构、基于PyObject指针）

## 3. 线性结构之链表

### 3.1 链表的基本概念
- 节点（Node）：数据域 + 指针域
- 头指针、尾指针
- 逻辑相邻但物理不一定相邻

### 3.2 链表的分类
- 单向链表（Singly Linked List）
- 双向链表（Doubly Linked List）
- 循环链表（Circular Linked List）
- 带头节点 vs 不带头节点

### 3.3 链表的核心操作及实现细节
- 创建节点与初始化
- 插入操作：
  - 头插法（O(1)）
  - 尾插法（有尾指针时为O(1)）
  - 指定位置插入（需遍历，O(n)）
- 删除操作：
  - 删除头节点（O(1)）
  - 删除尾节点（单向链表需O(n)，双向链表O(1)）
  - 删除指定值节点
- 查找操作：O(n)
- 反转链表（迭代与递归两种方式）

### 3.4 链表的优缺点与适用场景
- 优点：动态扩容、插入删除高效（已知位置时）
- 缺点：不能随机访问、额外内存开销（指针）、缓存不友好
- 适用：频繁插入删除、大小动态变化、实现栈/队列

### 3.5 数组 vs 链表 全面对比
- 表格对比（内存、访问、插入、删除、缓存、适用场景）

### 3.6 经典链表问题
- 判断链表是否有环（快慢指针）
- 找到环的入口节点
- 合并两个有序链表
- 链表的中间节点
- K个一组翻转链表

## 4. 线性结构之栈与队列

### 4.1 栈（Stack）——后进先出（LIFO）
- ADT定义：push, pop, peek/top, isEmpty, size
- 基于数组的实现（顺序栈）
- 基于链表的实现（链式栈）
- 栈的复杂度：所有操作O(1)

### 4.2 栈的经典应用
- 函数调用栈（递归实现）
- 表达式求值（中缀转后缀、后缀求值）
- 括号匹配检查
- 浏览器的前进后退
- 撤销操作（Undo）

### 4.3 队列（Queue）——先进先出（FIFO）
- ADT定义：enqueue, dequeue, front, isEmpty, size
- 基于数组的实现（循环队列，解决假溢出）
- 基于链表的实现（链式队列）
- 复杂度：所有操作O(1)（循环队列的判空判满条件）

### 4.4 队列的变种
- 双端队列（Deque）：两端都可插入删除
- 优先队列（Priority Queue）：基于堆实现，下文详述
- 阻塞队列（Blocking Queue）：多线程场景
- 延迟队列（Delay Queue）

### 4.5 队列的经典应用
- 广度优先搜索（BFS）的底层数据结构
- 消息队列（MQ）的基本模型
- 任务调度（FIFO调度）
- 缓冲区（生产者-消费者模型）

### 4.6 栈与队列的相互实现
- 用两个栈实现队列
- 用两个队列实现栈

## 5. 散列表（哈希表）

### 5.1 哈希表的基本思想
- 键值对（Key-Value）存储
- 通过哈希函数将键映射到数组索引
- 理想情况下：查找/插入/删除 O(1)

### 5.2 哈希函数的设计
- 好的哈希函数特性：确定性、均匀分布、快速计算
- 常见哈希函数：除法散列、乘法散列、MD5/SHA（加密用途）
- 整数/字符串/对象哈希的实现考虑

### 5.3 哈希冲突处理
- 链地址法（Separate Chaining）：每个槽位挂一个链表/红黑树
- 开放地址法（Open Addressing）：
  - 线性探测（Linear Probing）
  - 二次探测（Quadratic Probing）
  - 双重散列（Double Hashing）
- 再哈希法
- 建立公共溢出区

### 5.4 负载因子与动态扩容
- 负载因子 = 元素个数 / 表长度
- 扩容阈值（通常0.75）
- 扩容时的 rehash 操作（代价较高，但均摊后仍为O(1)）

### 5.5 哈希表在编程语言中的实现
- Python 的 dict 和 set（基于开放地址法，二次探测）
- Java 的 HashMap（链地址法 + 红黑树优化）
- C++ 的 unordered_map（链地址法）
- Go 的 map（链地址法 + 渐进式扩容）

### 5.6 哈希表的优缺点与适用场景
- 优点：极快的查找速度
- 缺点：无序、内存开销较大、有冲突风险、对哈希函数敏感
- 适用：缓存系统、数据库索引、去重、计数

### 5.7 哈希攻击（Hash DoS）
- 恶意构造大量哈希冲突的键，导致性能退化
- 防御手段：随机化哈希种子（如Python的PYTHONHASHSEED）

## 6. 树形结构基础

### 6.1 树的定义与术语
- 树是 n 个节点的有限集合（n≥0）
- 根节点、父节点、子节点、兄弟节点
- 叶子节点、内部节点、度、深度、高度、层数
- 森林：多棵互不相交的树的集合

### 6.2 树的存储方式
- 双亲表示法（数组存储父节点下标）
- 孩子表示法（链表/数组存储所有子节点）
- 孩子兄弟表示法（左孩子右兄弟，用于一般树转二叉树）

### 6.3 树的遍历方式
- 深度优先遍历（DFS）：
  - 先序遍历（根-左-右）
  - 中序遍历（左-根-右）
  - 后序遍历（左-右-根）
- 广度优先遍历（BFS）：层序遍历（借助队列）

### 6.4 树的常见应用
- 文件系统目录结构
- 组织架构图
- XML/JSON 的 DOM 解析树
- 决策树（机器学习）

## 7. 二叉树与二叉搜索树

### 7.1 二叉树的定义与性质
- 每个节点最多有两个子节点（左孩子、右孩子）
- 满二叉树、完全二叉树、完美二叉树
- 性质：
  - 第 i 层最多 2^(i-1) 个节点
  - 深度为 h 的二叉树最多 2^h - 1 个节点
  - 叶子节点数 = 度为2的节点数 + 1

### 7.2 二叉树的存储
- 顺序存储（数组，适用于完全二叉树）
- 链式存储（二叉链表）

### 7.3 二叉树的遍历实现（递归与非递归）
- 递归遍历（简洁但可能栈溢出）
- 非递归遍历（利用显式栈模拟系统栈）
- Morris 遍历（O(1)空间复杂度）

### 7.4 二叉搜索树（BST）的定义
- 左子树所有节点值 < 根节点值 < 右子树所有节点值
- 中序遍历得到有序序列

### 7.5 BST 的核心操作
- 查找：O(h)，最坏 O(n)
- 插入：O(h)
- 删除：三种情况（叶子节点、单孩子节点、双孩子节点——找前驱或后继替换）
- 查找最大/最小值

### 7.6 BST 的性能问题
- 退化为链表（插入有序数据时）
- 引出平衡二叉树的需求

## 8. 平衡二叉树（AVL与红黑树）

### 8.1 为什么需要平衡树
- 保证树的高度为 O(log n)
- 确保所有操作稳定在 O(log n)

### 8.2 AVL 树
- 平衡因子 = 左子树高度 - 右子树高度（绝对值 ≤ 1）
- 四种旋转操作：LL、RR、LR、RL
- 插入和删除后的平衡调整
- AVL 的优缺点：查询极快，但插入删除旋转开销较大

### 8.3 红黑树（Red-Black Tree）
- 五条性质（节点颜色、根黑、叶黑、红子黑、黑高相同）
- 红黑树 vs AVL：查询稍慢（但仍为O(log n)），插入删除更快（旋转次数少）
- 红黑树在工业界的广泛应用：
  - Java 的 TreeMap/TreeSet
  - C++ STL 的 std::map/std::set
  - Linux 内核的调度器、内存管理

### 8.4 B树与B+树（简介）
- 多路搜索树，降低磁盘I/O次数
- B+树在数据库索引中的核心地位（MySQL InnoDB）
- 2-3树、2-3-4树作为B树的特例

## 9. 堆与优先队列

### 9.1 堆的定义与性质
- 完全二叉树结构
- 大根堆（父节点 ≥ 子节点）vs 小根堆（父节点 ≤ 子节点）
- 数组存储（从索引1开始更便于计算子节点：2i, 2i+1）

### 9.2 堆的核心操作
- 上浮（swim / heapify-up）：用于插入
- 下沉（sink / heapify-down）：用于删除堆顶
- 建堆（heapify）：O(n) 的批量建堆算法
- 插入：O(log n)
- 删除堆顶：O(log n)
- 获取堆顶：O(1)

### 9.3 堆排序（Heap Sort）
- 建堆 + 反复删除堆顶到数组末尾
- 时间复杂度 O(n log n)，空间 O(1)
- 不稳定排序

### 9.4 优先队列（Priority Queue）
- 基于堆实现的 ADT
- 应用场景：
  - Dijkstra 最短路径算法（堆优化）
  - Huffman 编码
  - 多路归并（K-way merge）
  - 求 Top K 大/小元素

### 9.5 其他堆变种
- 二项堆、斐波那契堆（学术用途）
- 配对堆（实际性能好）

## 10. 图结构基础

### 10.1 图的定义与术语
- 顶点（Vertex/Node）和边（Edge）
- 有向图 vs 无向图
- 带权图 vs 无权图
- 简单图、完全图、稀疏图、稠密图
- 度（有向图中分为入度和出度）
- 路径、简单路径、环
- 连通分量（无向图）/ 强连通分量（有向图）

### 10.2 图的存储方式
- 邻接矩阵（Adjacency Matrix）：O(V²)空间，查询边 O(1)，适合稠密图
- 邻接表（Adjacency List）：O(V+E)空间，适合稀疏图，最常用
- 边集数组（Edge List）：适合需要遍历所有边的场景（如Kruskal算法）
- 十字链表（有向图优化）/ 邻接多重表（无向图优化）

### 10.3 图的遍历
- 深度优先搜索（DFS）：递归/栈，标记访问状态
- 广度优先搜索（BFS）：队列，逐层扩展
- DFS 的时间戳：发现时间、完成时间
- DFS 生成森林

### 10.4 图的复杂度
- 邻接表 BFS/DFS：O(V + E)
- 邻接矩阵 BFS/DFS：O(V²)

## 11. 图的遍历与最短路径

### 11.1 拓扑排序（Topological Sort）
- 适用于有向无环图（DAG）
- Kahn 算法（基于入度）
- DFS 逆后序（基于完成时间）
- 应用：课程安排、编译依赖、任务调度

### 11.2 最小生成树（MST）
- Prim 算法（加点法，贪心，邻接表+堆 O(E log V)）
- Kruskal 算法（加边法，并查集，O(E log E)）
- 应用：网络铺设、电路板设计

### 11.3 单源最短路径
- Dijkstra 算法（非负权图，堆优化 O(E log V)）
- Bellman-Ford 算法（可处理负权边，检测负环，O(VE)）
- SPFA（队列优化Bellman-Ford，但最坏仍 O(VE)）

### 11.4 多源最短路径
- Floyd-Warshall 算法（动态规划，O(V³)，可处理负权边）
- 应用：导航系统、网络路由协议

### 11.5 关键路径（AOE网）
- 事件最早/最晚发生时间
- 工程工期计算

## 12. 高级数据结构概览

### 12.1 并查集（Union-Find / Disjoint Set）
- 核心操作：find（路径压缩）、union（按秩合并）
- 近乎 O(1) 的均摊时间复杂度
- 应用：连通性问题、最小生成树 Kruskal、图像分割

### 12.2 线段树（Segment Tree）
- 区间查询（RMQ、区间和、区间最值）
- 单点更新、区间更新（懒惰标记 lazy propagation）
- 时间复杂度 O(log n) 每次操作
- 应用：动态区间统计

### 12.3 树状数组（Fenwick Tree / BIT）
- 支持单点更新 + 前缀查询
- 相比线段树代码更简洁、常数更小
- 可支持区间更新 + 单点查询（差分技巧）

### 12.4 字典树（Trie）
- 高效存储和检索字符串集合
- 前缀匹配、自动补全
- 与哈希表相比：内存稍大，但支持前缀搜索

### 12.5 后缀数组与后缀自动机（简介）
- 文本搜索、最长重复子串

### 12.6 跳表（Skip List）
- 随机化数据结构，实现有序集合
- 平衡树的替代方案，实现简单
- Redis 的有序集合（ZSET）底层实现

### 12.7 布隆过滤器（Bloom Filter）
- 概率性数据结构，判断"某元素一定不存在"或"可能存在"
- 空间效率极高，存在误判率
- 应用：缓存穿透防护、爬虫URL去重

## 13. 数据结构的选择策略

### 13.1 决策流程
- 需要存储什么类型的键值数据？
- 需要支持哪些操作（查找、插入、删除、范围查询、有序遍历）？
- 数据量大小、数据是否动态变化？
- 时间优先还是空间优先？

### 13.2 场景对照表

| 应用场景                   | 推荐数据结构      | 原因                 |
| -------------------------- | ----------------- | -------------------- |
| 快速查找（无顺序要求）     | 哈希表            | O(1) 查找            |
| 有序数据查找               | 红黑树 / 跳表     | O(log n) 有序遍历    |
| 固定大小、频繁随机读取     | 数组              | O(1) 访问 + 缓存友好 |
| 频繁插入删除（两端）       | 双向链表          | O(1) 两端操作        |
| 频繁插入删除（中间）       | 跳表 / 树         | 平衡性能             |
| 优先级任务调度             | 堆（优先队列）    | O(log n) 取最值      |
| 图的最短路径               | 邻接表 + 堆       | 经典组合             |
| 区间查询/统计              | 线段树 / 树状数组 | 高效区间操作         |
| 字符串前缀匹配             | 字典树（Trie）    | 按前缀快速检索       |
| 集合成员判断（可容忍误判） | 布隆过滤器        | 极省空间             |

### 13.3 时空权衡原则
- 空间换时间：缓存、预计算、哈希表
- 时间换空间：压缩存储、惰性计算

## 14. 复杂度分析总览

### 14.1 各数据结构时间复杂度对比表

| 数据结构   | 访问     | 查找     | 插入     | 删除     | 平均/最坏      |
| ---------- | -------- | -------- | -------- | -------- | -------------- |
| 数组       | O(1)     | O(n)     | O(n)     | O(n)     | 平均           |
| 动态数组   | O(1)     | O(n)     | O(1)*    | O(n)     | *摊还          |
| 单向链表   | O(n)     | O(n)     | O(1)†    | O(1)†    | †已知位置      |
| 双向链表   | O(n)     | O(n)     | O(1)†    | O(1)†    | †已知位置      |
| 栈         | O(1)     | -        | O(1)     | O(1)     | 仅栈顶         |
| 队列       | O(1)     | -        | O(1)     | O(1)     | 仅队首/队尾    |
| 哈希表     | N/A      | O(1)     | O(1)     | O(1)     | 平均；最坏O(n) |
| 二叉搜索树 | O(log n) | O(log n) | O(log n) | O(log n) | 平均；最坏O(n) |
| AVL树      | O(log n) | O(log n) | O(log n) | O(log n) | 严格           |
| 红黑树     | O(log n) | O(log n) | O(log n) | O(log n) | 严格           |
| 堆         | O(1)‡    | -        | O(log n) | O(log n) | ‡取堆顶        |

### 14.2 空间复杂度对比
- 数组/动态数组：O(n)
- 链表：O(n)（额外指针开销）
- 哈希表：O(n)（负载因子约束）
- 树：O(n)（指针开销较大）
- 图（邻接表）：O(V+E)
- 图（邻接矩阵）：O(V²)

### 14.3 性能分析中的常见陷阱
- 忽略常数因子（哈希表的O(1)实际比数组O(1)慢很多）
- 忽略缓存友好性（链表性能实际低于数组预期）
- 忽略最坏情况（哈希冲突、BST退化为链表）
